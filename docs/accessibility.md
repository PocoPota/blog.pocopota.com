# アクセシビリティ

## 基本方針

- ブラウザやユーザーの支援機能を不用意に無効化しない。
- キーボード操作で主要な導線を利用できるようにする。
- フォーカス中の要素が視覚的に分かる状態を保つ。
- 文字サイズ、行間、コントラストは読みやすさを優先して設計する。
- アニメーションやスクロール演出は、動きを減らしたいユーザー設定を尊重する。
- まずは HTML の標準要素と標準の挙動を使い、ARIA は標準要素だけで表現できない場合に補助として使う。

## このプロジェクトで担保する最低ライン

- `bun run ci` が通る状態を維持する。
- ページごとに一意で内容を表す `<title>` と、必要に応じた `description` を設定する。
- `<html lang>` はサイトの主言語に合わせる。多言語ページでは該当部分に `lang` を付ける。
- 各ページは原則として 1 つの `<main>` を持ち、主要コンテンツへスキップできる。
- 見出しはページ構造に沿って使い、見た目のためだけにレベルを飛ばさない。
- リンクは遷移、ボタンは操作に使う。クリックできる `div` / `span` を作らない。
- すべての操作可能な UI はキーボードだけで到達、実行、離脱できる。
- 操作可能な UI には視覚的なフォーカス表示を残す。
- アイコンだけの操作、画像リンク、フォーム入力には、支援技術に伝わる名前を用意する。
- 画像には用途に応じた `alt` を付ける。装飾画像は空の `alt=""` にする。
- 色だけで状態や意味を伝えない。テキスト、アイコン、形、補足文などを併用する。
- 本文、リンク、ボタン、フォーカスリングは背景とのコントラストを確認する。
- 自動再生、点滅、強い動き、スクロール演出は避ける。必要な動きは `prefers-reduced-motion` に対応する。
- フォームは `label`、エラー文、入力例、必須/任意の情報が分かるようにする。
- モーダル、メニュー、タブなどの独自 UI は、キーボード操作、フォーカス管理、スクリーンリーダーでの名前を確認する。

## テンプレートの基盤設定

- `text-size-adjust: 100%` を指定し、モバイルブラウザの文字サイズ調整を抑えつつ、`none` でユーザー設定を強く潰さないようにする。
- `body` に読みやすい基準の `line-height` を指定する。
- `prefers-reduced-motion: reduce` で、動きを減らしたいユーザー向けにスクロールやアニメーションを抑制する。
- `:focus-visible` のフォーカスリングをグローバルに定義し、キーボード操作時の現在位置を見失いにくくする。
- スキップリンクと `main` の `tabindex="-1"` により、キーボード操作で本文へ移動しやすくする。

## 自動検査で担保するルール

### ESLint

`eslint-plugin-astro` の `flat/jsx-a11y-strict` を有効にし、Astro コンポーネント内のアクセシビリティ違反を検出する。

主に以下を検出対象にする。

- `img`、`area`、`input type="image"` などの代替テキスト不足。
- 空のリンク、空の見出し、空の iframe title。
- 不正な `aria-*`、存在しない role、role に必要な `aria-*` の不足。
- `aria-hidden="true"` が付いたフォーカス可能要素。
- 非インタラクティブ要素への click/key event 付与。
- インタラクティブ要素に不適切な role を付ける実装。
- 正の `tabindex`。
- mouse event だけに依存する interaction。
- `accesskey`、`autofocus`、点滅系要素など、ユーザー操作を阻害しやすい実装。

### Stylelint

`@double-great/stylelint-a11y` を有効にし、CSS/SCSS/Astro 内のスタイル起因の問題を検出する。

有効なルールは以下。

- `a11y/font-size-is-readable`: 小さすぎる文字サイズを避ける。
- `a11y/media-prefers-reduced-motion`: animation / transition を使う場合に `prefers-reduced-motion` 対応を求める。
- `a11y/no-outline-none`: 代替なしに outline を消す実装を避ける。
- `a11y/selector-pseudo-class-focus`: hover だけに依存したスタイルを避け、focus 状態も用意する。

### 実行コマンド

- `bun run lint:check`: Astro/TypeScript/JavaScript の静的検査。
- `bun run stylelint:check`: CSS/SCSS/Astro のスタイル検査。
- `bun run check`: lint、format、stylelint のまとめ検査。
- `bun run ci`: `check` と `astro check` を実行する CI 向け検査。

## 自動検査では担保しきれないこと

自動検査は、実際の分かりやすさや操作感を完全には判定できない。レビューでは以下を目視とキーボード操作で確認する。

- リンクテキストやボタン文言が、単体で目的を理解できる。
- 画像の `alt` が、その画像の文脈上の役割に合っている。
- 見出しだけを拾ってもページ構造が理解できる。
- Tab キーで移動した時の順序が見た目と意味の順序に合っている。
- フォーカスリングがヘッダー、モーダル、固定要素、背景色に隠れない。
- hover で出る情報や操作が、focus または click/tap でも使える。
- エラー、成功、選択中、現在地などの状態が色だけに依存していない。
- 文字サイズを拡大しても、テキストが重なる、欠ける、操作できなくなる状態にならない。
- 画面幅が狭い時も、主要導線とフォーム操作が失われない。

## 個別プロジェクトで設定する事項

### aタグ

リンクの見た目はプロジェクトごとの色設計やUIトーンに依存するため、テンプレートでは最低限の表現に留める。

- テンプレートでは `color: inherit` と hover / focus-visible 時の `text-decoration: none` のみ指定する。
- 本文リンク、ナビ、カードリンク、ボタン風リンクなどで求める見た目が違うため、リンク色、下線の太さ、下線位置などは各プロジェクトまたはコンポーネントで指定する。
- サイト全体でリンク表現を統一する場合は、プロジェクトの `global.scss` で `a` または本文領域のセレクタに追加指定する。
- ナビ、ボタン、カードなど特定UIのリンク表現は、各コンポーネントの CSS Modules に指定する。
- `focus-visible` はグローバルで担保するため、リンク側で個別に消さない。`outline: none` を使う場合は、代替のフォーカス表示を必ず用意する。

### スキップリンク

スキップリンクはキーボード操作時に本文へ直接移動するための導線として用意する。テンプレートではフォーカス時に見やすい最低限の装飾を指定する。

- 背景色、文字色、余白、角丸などは、各プロジェクトのブランドやUIトーンに合わせて変更してよい。
- フォーカス時に画面内へ表示され、他のUIに隠れない状態は維持する。
- 装飾を変更する場合も、背景とのコントラストとクリックしやすい余白を確保する。

### 色とコントラスト

ブランドカラーや背景色を決める際は、本文、リンク、ボタン、フォーカスリングが十分に識別できるコントラストを確保する。

- 通常テキストは WCAG AA 相当の 4.5:1 以上を目安にする。
- 大きい文字や太字の大きい文字は 3:1 以上を目安にする。
- ボタン、入力欄、フォーカスリングなど UI の境界や状態も、背景との差が分かるようにする。

### タイポグラフィ

見出し、ボタン、フォームなどで基準の `line-height` が合わない場合は、読みやすさとレイアウトの両方を確認して個別に調整する。

- 本文は `line-height: 1.5` 以上を目安にし、このテンプレートでは `body` に `1.7` を指定する。
- 長文の中央寄せや均等割り付けは読みづらくなりやすいため避ける。
- 文字サイズはユーザーの拡大設定を前提にし、固定高さの中に無理に閉じ込めない。

### 画像

- 情報を伝える画像には、その情報が伝わる `alt` を設定する。
- 周辺テキストと同じ情報を繰り返すだけの画像や装飾画像は `alt=""` にする。
- リンク内の画像は、リンク先や操作内容が分かる代替テキストにする。
- 画像内テキストはなるべく避ける。必要な場合は同等のテキスト情報を HTML 側にも用意する。

### フォーム

- 入力欄には対応する `label` を用意する。
- placeholder を label の代わりにしない。
- エラーは色だけでなく、テキストで内容と修正方法を伝える。
- エラー文と入力欄の関係は `aria-describedby` などで結び付ける。
- 必須項目は視覚的にも支援技術にも伝わるようにする。

### インタラクション

独自UIを作る場合は、マウス操作だけでなくキーボード操作、フォーカス順、スクリーンリーダーでの名前を確認する。

- クリック可能な領域は、原則として実体を `<button>` または `<a>` にする。
- 操作対象の最小サイズは 44px 四方を目安にする。
- 開閉 UI は、開閉状態が視覚的にも支援技術にも伝わるようにする。
- モーダルやドロワーは、開いた時に適切な位置へフォーカスを移し、閉じた時に元の操作元へ戻す。
- キーボード操作を独自実装する場合は、Tab、Enter、Space、Escape、矢印キーの期待挙動を確認する。

## レビュー時の確認観点

- `bun run ci` が通っている。
- lint を無効化している場合、その理由と代替確認方法がコメントまたはレビュー上で説明されている。
- link と button の使い分けが正しい。
- 見出し、ランドマーク、リスト、テーブルなどの HTML 構造が見た目ではなく意味に沿っている。
- キーボードだけで主要導線を操作できる。
- フォーカス表示が見える。
- 画像、アイコンボタン、フォーム部品に accessible name がある。
- 色、動き、位置、形だけに依存した情報伝達になっていない。
- PC 幅と mobile 幅の両方で、拡大表示時に主要操作が破綻しない。

## 例外運用

lint ルールを無効化する場合は、対象を最小範囲にし、理由を残す。

- 原則としてファイル全体の無効化は避ける。
- デザイン都合だけで `outline: none` や正の `tabindex` を許可しない。
- WAI-ARIA の複雑な widget を作る場合は、実装前に標準要素で代替できないか確認する。
- 自動検査で検出できない問題があるため、重要な導線は手動のキーボード操作確認を必須にする。
