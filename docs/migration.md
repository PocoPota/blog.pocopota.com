# blog.pocopota.com 移行計画

blog.pocopota.comをHugoからAstroに作り直し、pocopota.hateblo.jpの記事も新サイトに統合する。この文書は、移行後も維持するURLと、記事ごとの移し方と、作業の手順を定める。

## 1. 前提

### 1.1 blog.pocopota.comの現行構成

| 項目           | 内容                                                                                                                                                                             |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 静的サイト生成 | Hugo 0.94.2。テーマはhugo_theme_robustを`layouts/`で上書きしている                                                                                                               |
| スタイル       | `assets/custom.scss`をgulpでコンパイルし、`layouts/partials/custom.css`に出力                                                                                                    |
| 記事           | `content/*.md`の28本。front matterはTOML（`+++`）。本文の多くは、はてなブログから移したHTML                                                                                      |
| 画像           | `static/images/`。記事画像は`static/images/content/`の129ファイル                                                                                                                |
| デプロイ       | `master`へのpushでGitHub Actionsがビルドし、`gh-pages`ブランチへ出力する。ワークフローは廃止済みの`ubuntu-18.04`ランナーを指定しており、`gh-pages`への最後のデプロイは2023-03-10 |
| ドメイン       | `static/CNAME`にblog.pocopota.com                                                                                                                                                |
| 計測・コメント | Google Analytics `G-DZ9TTYPEYH`、Disqus `XYW`                                                                                                                                    |

### 1.2 pocopota.hateblo.jpの現状

| 項目   | 内容                                                                                              |
| ------ | ------------------------------------------------------------------------------------------------- |
| 記事   | 6本（2023-12〜2025-05）                                                                           |
| 画像   | はてなフォトライフ（`cdn-ak.f.st-hatena.com`）に20枚。本文の画像19枚と、本文にないアイキャッチ1枚 |
| ページ | 記事のほかにトップと`/about`                                                                      |

### 1.3 移行後の構成

- [sohosai/astro-template26](https://github.com/sohosai/astro-template26)をもとにする。Astro 7.3、bun、Node 24（`.node-version`）、`@astrojs/sitemap`、ESLint・Prettier・Stylelint、lefthookの構成。
- 同じリポジトリで作り、GitHub Pagesからblog.pocopota.comとして配信する。pocopota.hateblo.jpは新サイトへの案内だけを残す（5.3）。
- デザインは最低限のものを新しく作る。旧記事の本文にだけ、旧サイトのスタイルの一部を当てる（4.1）。

### 1.4 記事の区分

記事を次の2つに分けて扱う。

| 区分   | 対象                                               | 置き場所              | 一覧・RSS | sitemap | URL                  |
| ------ | -------------------------------------------------- | --------------------- | --------- | ------- | -------------------- |
| 旧記事 | blog.pocopota.comの現行の28本                      | `src/content/legacy/` | 出さない  | 含める  | 現行と同じ`/<slug>/` |
| 新記事 | pocopota.hateblo.jpから統合する6本と、今後書く記事 | `src/content/posts/`  | 出す      | 含める  | `/<slug>/`           |

旧記事は、検索結果やリンクから閲覧できる状態だけを保つ。sitemapに含めるのは、外すと検索エンジンのインデックスから落ちやすくなるため。

## 2. 維持するURL

## 3. 一覧ページ

新サイトにタグとカテゴリは作らない。一覧ページは新記事だけを並べ、Astroの`paginate()`で生成する。`src/pages/[...page].astro`から、トップ`/`を1ページ目、2ページ目以降を`/2/`、`/3/`として出す。1ページは10件。

## 4. 旧記事の移行

### 4.1 置き場所とレイアウト

- 旧記事は`src/content/legacy/`に置き、新記事とは別のコレクションにする。一覧・RSSは新記事のコレクションだけを読む。
- ページは新記事と同じ`src/pages/[slug].astro`から生成する。本文を包む要素に、旧記事のときだけ`legacy`クラスを付ける。
- 旧記事の本文は、次のクラスに依存している。このうち商品リンクボックスとチェックリストの囲みのスタイルを旧`assets/custom.scss`から`src/components/post/Article.module.scss`に移し、`legacy`クラスの中だけで効くようにする。ほかのクラスは新記事と共通の本文スタイルで表示する。
- Font AwesomeのCSSと、Xの埋め込み用の`widgets.js`は、本文がそれを使う記事でだけ読み込む。

- `css-load-circle`が参照する`/images/content/20210906071333.png`はリポジトリにない。現行サイトでも表示されていない。

### 4.4 変換結果の確認

MarkdownパーサーがHugo（goldmark）からAstro（remark）に変わるため、HTML混じりの本文の解釈が変わることがある。28本それぞれについて、`gh-pages`ブランチの`/<slug>/index.html`と新サイトの出力から本文のテキストを取り出して比べる。差分は、4.3で置き換えたブログカードの箇所と、公開版に反映されていなかったソースの修正（`ja-nadeshiko-lang`のコード）だけになる。

### 5.3 はてなブログ側の扱い

はてなブログはサーバー側の転送を設定できない。そのためD8のとおり、ブラウザで転送するスクリプトと、記事本文の案内の両方を置く。

転送スクリプトは、はてなブログの「デザイン > カスタマイズ > ヘッダ > タイトル下」に貼る。5.1の記事は対応する新URLへ、それ以外のページは新サイトのトップへ移動する。

```html
<script>
	(function () {
		var map = {
			"/entry/2024/09/06/001229": "/2023-review/",
			"/entry/helloworld": "/hello-world-2024/",
			"/entry/itf-coins-ac": "/itf-coins-ac/",
			"/entry/adcale-itf-ac": "/adcale-itf-ac/",
			"/entry/i-am-fe": "/i-am-fe/",
			"/entry/darts-at-home": "/darts-at-home/",
		};
		location.replace(
			"https://blog.pocopota.com" + (map[location.pathname] || "/"),
		);
	})();
</script>
```

各記事の本文は、次の1文と新URLへのリンクに差し替える。スクリプトを実行しない検索エンジンのクローラーや、JavaScriptを切っている読者に移転先を伝えるため。

> この記事は https://blog.pocopota.com/<新URLのslug>/ に移転しました。

## 6. 決定事項

| ID  | 項目                             | 決定                                                                                                                                      |
| --- | -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | sitemapのURL                     | `@astrojs/sitemap`は`/sitemap-index.xml`を出す。Search Consoleの登録をこれに差し替える                                                    |
| D2  | 新記事のURL                      | 旧記事と同じ`/<slug>/`にする。slugの重複はビルド時に検出してエラーにする                                                                  |
| D3  | 本文中のはてなブログへのリンク   | 同じslugの新URL（`/<slug>/`）に書き換える。ブログカードのiframeは通常のリンクに置き換える                                                 |
| D4  | Disqusのコメント欄               | 廃止する                                                                                                                                  |
| D5  | Google Analytics                 | 公開中のページに出ている`G-DZ9TTYPEYH`を引き継ぐ                                                                                          |
| D6  | デプロイ方式                     | `actions/deploy-pages`で直接デプロイし、`gh-pages`ブランチは使わない。リポジトリのPages設定のSourceを「GitHub Actions」に切り替える       |

## 7. 手順

1. テンプレートのファイルを取り込む。テンプレートの`docs/`にある規約文書は、この文書と同じ`docs/`に置く。
2. `astro.config.mjs`に`site: "https://blog.pocopota.com"`、`trailingSlash: "always"`を設定する。テンプレートのREADMEにある「プロジェクト開始時に変更する項目」を済ませる。
3. `static/`を`public/`に移す（2.2）。
4. 旧記事を`src/content/legacy/`に移し、front matterを変換する（4.2、4.3）。
5. 記事ページ`src/pages/[slug].astro`と本文のスタイルを作る（4.1）。
6. 新デザインの一覧ページ（3節）、新記事のコレクション、RSS、404を作る。
7. はてなブログ記事を取得し、画像とあわせて`src/content/posts/`に移す（5.1、5.2）。
8. ビルドし、2節のURLと5.1の新URLがすべて`dist/`にあることと、4.4の本文の差分を確かめる。
9. Hugo関係のファイル（`config.toml`、`layouts/`、`themes/`、`archetypes/`、`resources/`、`assets/`、`gulpfile.js`、旧`package.json`）を削除する。
10. デプロイ用ワークフローを新しいものに差し替え、Pagesの設定を変えてから`master`にマージする。
11. 公開後、2節のURLと5.1の新URLを本番で開いて確かめ、Search Consoleにsitemapを登録する。
12. pocopota.hateblo.jpをD8のとおり変更する。
